# Evidencia 01 — Seguridad y autorización (2026-11-18)

- **Atributo:** Seguridad y autorización (autenticación JWT y control por rol).
- **Herramientas:** `curl`, `docker compose exec postgres psql`, `python3` (solo para parsear JSON y ocultar secretos).
- **Procedimiento:** login demo válido; llamadas a `POST /api/v1/offers/sync` sin JWT, con JWT inválido, con JWT de productor y con JWT de usuario temporal `BUYER` (creado solo para la prueba y eliminado después).
- **Comando reproducible (secretos omitidos):**
  ```bash
  API=http://localhost:3000/api/v1
  TOKEN=$(curl -s -X POST "$API/auth/login" -H 'Content-Type: application/json' \
    -d '{"email":"productor@campora.demo","password":"<DEMO_PASSWORD>"}' \
    | python3 -c 'import json,sys;print(json.load(sys.stdin)["accessToken"])')
  BODY='{"clientOfferId":"22222222-2222-4222-8222-222222222222","productName":"Mango Tommy","category":"Fruta","quantity":120,"unit":"kg","pricePerUnit":3500,"currency":"COP","municipality":"Espinal, Tolima","description":"PRUEBA-SEGURIDAD-2026-11-18"}'
  curl -s -o /dev/null -w '%{http_code}\n' -X POST "$API/offers/sync" -H 'Content-Type: application/json' -d "$BODY"
  curl -s -o /dev/null -w '%{http_code}\n' -X POST "$API/offers/sync" -H 'Content-Type: application/json' -H 'Authorization: Bearer invalid.token.value' -d "$BODY"
  curl -s -o /dev/null -w '%{http_code}\n' -X POST "$API/offers/sync" -H 'Content-Type: application/json' -H "Authorization: Bearer $TOKEN" -d "$BODY"
  ```
- **Criterio de aceptación:** sin JWT → `401`; JWT inválido → `401`; JWT válido de productor con datos válidos → creación/201; otro rol → rechazo por permisos (`403`).
- **Resultado observado:**
  | Caso | HTTP | Respuesta depurada |
  | --- | --- | --- |
  | Login productor demo | 201* | `{"login":"ok","role":"PRODUCER"}` (token y `userId` omitidos) |
  | Sin JWT | 401 | `{"message":"Unauthorized","statusCode":401}` |
  | JWT inválido | 401 | `{"message":"Unauthorized","statusCode":401}` |
  | JWT productor + datos válidos | 201 | `{"synced":true,"offer.id":"<redacted>","clientOfferId":"22222222-2222-4222-8222-222222222222","status":"PUBLISHED"}` |
  | JWT `BUYER` temporal | 403 | `{"message":"No autorizado","statusCode":403}` |
  | Limpieza | — | usuario temporal eliminado; `SELECT count(*) ... = 0`; solo queda el usuario demo original |
  \* El login responde 201 en esta versión de NestJS; se registró el código real devuelto.
